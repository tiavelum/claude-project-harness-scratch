# Harness bootstrap

This document is the harness's living self-description: enough for a fresh
Claude account, with no other context, to recreate the whole arrangement. It
draws only on the living documents of this repo, never on the archived seed.
It must be updated with every structural change (docs/operations.md).

## What the arrangement is

One private GitHub repo, tiavelum/claude-project-harness, paired with exactly
one Claude project of the same name, and one seed repository,
tiavelum/claude-project-harness-seed, holding a lossless snapshot of the
harness (decision 0006). The harness repo is the only durable surface where
content changes; the project's Instructions field is a pure pointer pasted
from a master file in the repo; the seed is regenerated from the harness and
never edited. Why it is built this way: docs/design.md. What the platform
allows: docs/platform.md. The general engineering norms it builds on:
tiavelum/engineering-standards, consumed per its consumer contract starting
at index.yaml.

## Recreating it

The seed clone is the recreation path. If the harness repository is gone or
must be recreated elsewhere:

1. Ensure a seed clone exists and is current (it is regenerated by the
   "generate a seed clone" operation; if the harness still exists, run that
   first).
2. Follow the planting procedure in the seed repository's README (master:
   claude/seed-clone-readme.md). It recreates the repository content and the
   issues, verifies every file against the manifest, and guides the manual
   steps: create the repository, create the Claude project, grant the
   connector, paste the Instructions field.
3. Birth check: a fresh session in the project reads README.md and runs one
   operation from docs/operations.md without further help.

On another account, the same procedure applies with the owner name adjusted
in the pushed files; nothing else is account-specific.

## Manual residue, honestly

Creating, deleting and renaming repos, pasting the Instructions field,
first-time installing account skills, pressing Sync on project knowledge,
deciding the connector grant scope, and keeping any sensitive-data file out
of git are manual, and stay manual until docs/platform.md says otherwise.

## What the seed does not carry

Git history and issue comments live only in the harness repository. A
mirror clone into a connected folder is the complementary backup for them
(issue #15).
